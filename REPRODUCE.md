## Dates

Each commit is dated at noon (Asia/Karachi) on the day the change took effect. The other dates, enacted and published, are trailers.

When a law gives no date of its own, the default rule applies: Not applied: this record dates each Act by the day the Sindh Code says its codified text is updated till, not by the day it or any amendment came into force. https://sindhlaws.gov.pk/

## How the history is built

`tools/build.py` turns the corpus into this history in one pass: one commit per law, on the day it took effect. The same corpus always gives the same commit hashes. `tools/check_repo.py` reads every version back from git and compares it with the corpus. `tools/on.py` shows the law as it stood on any date. The corpus format is described in `tools/SCHEMA.md`.

## Decisions made by hand

- Current text only: the Sindh Code gives each codified Act or Ordinance as one PDF "updated till" a stated date, with no earlier consolidated text, so each is one version ("oldest version available", first_law null), dated by that date at noon in Karachi and credited to the department, not to an amending Act.
- The footnotes (which say which Act substituted, inserted or omitted which words) are recorded in data/amendments.csv, not replayed as history; the footnote numbers in the text are dropped and the square brackets that mark amended words stay as printed.
- One file per section; the running head, the date and the preamble of the first text page are "000-title"; each Schedule is its own file. The marginal note beside a section (its heading) is the file's heading line. Chapter and part headings stand above the first section under them.
- Left out: the contents pages, running heads on later pages, page numbers, the "SCAN TO VERIFY" stamp and QR code the site adds to each download, and footnotes (kept in data/amendments.csv).
- Tables are read row by row as printed; their layout is not kept.
